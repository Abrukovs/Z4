# Ставка Дня — сайт спортивных прогнозов

Полноценный веб-проект: ежедневная «Ставка дня», прогнозы на сегодня, история
результатов, статистика (winrate, ROI, график прибыли), Telegram-бот с утренним
разбором и живыми ответами.

Этот файл — главный документ проекта. Прочитайте его, если хотите понять, из
чего состоит сайт, как его запустить с нуля и как восстановить на новом
сервере, если старый потерялся.

---

## 1. Из чего состоит проект (стек технологий)

| Технология | Что это и зачем |
|---|---|
| **Next.js 16** | Главный каркас сайта. Генерирует страницы и API-роуты (`/api/bets`, `/api/stats` и др.). Одна страница `/` с вкладками «Сегодня / История / Статистика». |
| **TypeScript** | Язык, на котором написан весь код. То же, что JavaScript, но со строгими типами — меньше ошибок. |
| **Bun** | Быстрый менеджер пакетов и среда выполнения (замена npm и Node.js). Именно им запускается и сайт, и Telegram-сервис. |
| **Tailwind CSS + shadcn/ui** | Стили и готовая библиотека красивых компонентов (кнопки, диалоги, табы). |
| **Prisma + SQLite** | Работа с данными. Подробно — в разделе 2 ниже. |
| **Git + GitHub** | Система резервных копий кода. Весь код проекта хранится в репозитории [github.com/Abrukovs/Z4](https://github.com/Abrukovs/Z4) и обновляется автоматически при каждом изменении. |

## 2. Что такое Prisma и что она делает

**Prisma — это «переводчик» между кодом сайта и базой данных.**

База данных (у нас — файл `db/custom.db` в формате SQLite) хранит все прогнозы,
результаты, статистику и настройки Telegram. Разговаривать с ней «напрямую»
на языке SQL неудобно и опасно (легко ошибиться). Prisma решает это так:

1. **Схема вместо таблиц.** В файле `prisma/schema.prisma` простым,
   читаемым языком описано, какие данные существуют — модели `Bet`
   (прогноз), `Tipster` (аналитик), `TelegramSettings` (настройки бота) и
   другие. Например: «каждый прогноз имеет коэффициент, статус
   (pending/won/lost/void) и флаг `isBetOfDay`».
2. **Автогенерация кода.** Из схемы Prisma сама генерирует типизированный
   клиент: `import { db } from '@/lib/db'`. В коде сайта вы пишете
   `db.bet.findMany({ where: { status: 'pending' } })` — и получаете
   готовые объекты TypeScript, без единой строчки SQL.
3. **Синхронизация с базой.** Команда `bun run db:push` создаёт/обновляет
   таблицы в `db/custom.db` точно по схеме. Поменяли модель в
   `schema.prisma` → запустили `db:push` → таблицы обновились.
4. **Безопасность типов.** Если попытаться записать в поле «коэффициент»
   строку вместо числа — TypeScript подсветит ошибку ещё до запуска.

**Итого:** Prisma не хранит данные сама — она лишь делает работу с
SQLite-файлом `db/custom.db` удобной и безопасной. Сам файл — это одна
маленькая база данных, лежащая рядом с кодом.

```
│   └── ui/                # Библиотека shadcn/ui
├── src/lib/               # Общий код: db.ts (подключение Prisma) и др.
├── prisma/schema.prisma   # СХЕМА ДАННЫХ (модели Bet, Tipster, ...)
├── db/custom.db           # Файл базы данных SQLite (секрет! в GitHub не идёт)

```

## 4. Запуск проекта с нуля (на любом сервере)

Нужен установленный **Bun** (проверить: `bun --version`; установить:
`curl -fsSL https://bun.sh/install | bash`).

```bash
# 1. Получить код (здесь или из GitHub)
git clone https://github.com/Abrukovs/Z4.git && cd Z4

# 2. Установить все зависимости (Next.js, Prisma, компоненты — займёт 1-3 мин)
bun install

# 3. Создать файл настроек окружения с путём к базе
echo 'DATABASE_URL=file:../db/custom.db' > .env

# 4. Создать базу данных по схеме Prisma (появится файл db/custom.db)
bun run db:push

# 5. Запустить сайт (порт 3000)
bun run dev
# → откройте http://localhost:3000 — при первом визите сайт сам
#   заполнится демо-данными (авто-сидинг), таблицы уже готовы

# 6. (Опционально) Запустить Telegram-бота — вторым терминалом
cd mini-services/telegram-bot && bun install && bun run dev
# → сервис на порту 3033; токен бота вводится на сайте в разделе
#   «Утренний разбор», он сохранится в базу и бот начнёт отвечать
```

Полезные команды:

| Команда | Что делает |
|---|---|
| `bun run dev` | Запустить сайт в режиме разработки (порт 3000) |
| `bun run lint` | Проверить качество кода (ESLint) |
| `bun run db:push` | Обновить таблицы БД по схеме `prisma/schema.prisma` |
| `bun run db:generate` | Перегенерировать Prisma-клиент |
| `bash .zscripts/git-sync.sh "текст"` | Сохранить изменения и отправить в GitHub |

## 5. Резервное копирование в GitHub

- **Что отправляется в GitHub:** весь код, схемы, конфигурация — всё, что
  нужно, чтобы поднять сайт с нуля.
- **Что НЕ отправляется (специально):**
  - `db/custom.db` — база данных. Внутри лежит **токен вашего
    Telegram-бота** (секрет), а репозиторий публичный. Утечка токена = чужие
    люди смогут управлять вашим ботом.
  - `mini-services/telegram-bot/data/` — состояние бота (там тоже токен).
  - `node_modules/`, скриншоты тестов, логи — мусор, который не нужен.
- **Как это происходит:** после каждого изменения кода запускается скрипт
  `.zscripts/git-sync.sh` — он фиксирует изменения (commit) и отправляет их
  в GitHub (push). Это происходит автоматически по расписанию и после каждой
  доработки.
- **Куда смотреть:** [github.com/Abrukovs/Z4](https://github.com/Abrukovs/Z4),
  ветка `main`. Каждый коммит — снимок кода на момент времени.

## 6. Аварийное восстановление («сервер умер, что делать?»)

Сценарий: этот сервер недоступен, код нужно поднять в другом месте.

1. На новом сервере установите Bun и выполните шаги из раздела 4
   (`git clone https://github.com/Abrukovs/Z4.git` и далее).
2. Демо-данные восстановятся автоматически (авто-сидинг при первом визите).
3. Ре-настроить Telegram: на сайте в разделе «Утренний разбор» снова
   вставьте токен бота (получить у [@BotFather](https://t.me/BotFather) —
   или тот же, если он не скомпрометирован) и нажмите «Подключить».
4. Готово — сайт работает.

**Промпт для ИИ-ассистента** (скопируйте целиком, если восстанавливаете
проект с помощью другого ИИ):

> Клонируй https://github.com/Abrukovs/Z4, прочитай README.md (особенно
> разделы 2, 4 и структуру папок) и запусти проект по инструкции:
> bun install, .env с DATABASE_URL=file:../db/custom.db, bun run db:push,
> bun run dev (порт 3000), плюс мини-сервис mini-services/telegram-bot
> (порт 3033, bun install && bun run dev в его папке). Код на TypeScript /
> Next.js 16 App Router / Prisma + SQLite / Tailwind + shadcn/ui.
> Проблем не ожидается: авто-сидинг заполнит БД при первом визите.

## 7. Безопасность — коротко

- Токены **никогда не коммитятся** в репозиторий (см. раздел 5).
- Токен доступа к GitHub хранится только локально на сервере в
  `.git/config` — в репозиторий он попасть не может.
- Если токен бота или токен GitHub когда-нибудь «засветился» публично —
  отзовите и выпустите новый (GitHub: Settings → Developer settings →
  Personal access tokens; Telegram: @BotFather → /revoke).
